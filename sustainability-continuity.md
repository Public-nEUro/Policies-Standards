# Sustainability and continuity

## Institutional basis

PublicnEUro is operated by the Neurobiology Research Unit (NRU) at Rigshospitalet, Region Hovedstaden, Denmark. The repository service is provided through service agreements between NRU and the institution responsible for each dataset.

The service agreement describes PublicnEUro as a data sharing service for brain-imaging research data that supports FAIR and GDPR-compliant sharing. It also defines the services provided by NRU, the responsibilities of the institution acting as data controller, the use of sub-processors, and the financial terms used to keep the service operating.

PublicnEUro uses Computerome as the hosting sub-processor for dataset files. Computerome provides secured read/write access, encryption in transit and geo-redundant backups. Computerome meets compliance requirements for EU health data storage and follows recognised security controls.

## Cost-recovery model

PublicnEUro is sustained through dataset-level fees rather than general user charges. The purpose of the fee model is to recover the real costs of keeping datasets available and governed over time. Fees are applied to datasets so PublicnEUro can pay its hosting provider, Computerome, and maintain the small amount of repository infrastructure needed for access control, metadata, administration and service continuity.

The model has three main cost components:

- an initial data instalment fee, which covers NRU administration and PublicnEUro data management at publication;
- a recurring management and maintenance fee, which contributes to continued repository administration, access management, metadata maintenance, user support, agreement handling and service oversight;
- a storage fee based on dataset size, which is used to cover subcontractor hosting costs for the dataset files.

Management and maintenance fees provide a modest overhead for the repository services that sit around storage. This includes the virtual machines and software services used by PublicnEUro, access-control workflows, account administration, signed agreement handling, metadata publication, DOI landing-page maintenance, security follow-up, and communication with data controllers and users.

Because the repository depends on dataset-level fees to cover Computerome hosting and repository overhead, non-payment can affect continued file availability. If a data controller does not pay the applicable fees, PublicnEUro may terminate or not renew the active hosting service in accordance with the agreement. This is offset by the one-time payment plan, which fits typical grant spending structure. In this case, an additional buffer fee is intended to cover potential increases in subcontractor prices over the covered period. For annual payment plans, the requested amount can be updated based on inflation and subcontractor prices.

## Service review and succession arrangements

PublicnEUro reviews sustainability at dataset level because each dataset can have different size, access mode, retention period and service needs. The Management Committee reviews free versus paid services and considers the sustainability of the platform as part of repository governance.

The service model distinguishes between:

- open hosting, where data may be openly available and no access-control service is needed;
- public controlled-access hosting, where metadata are public but data access is controlled;
- private hosting, where access is limited to specified users or groups and additional management fees may apply;
- cold archival storage, where data are retained but retrieval is delayed;
- retirement, where files are no longer held by PublicnEUro but metadata and a data-controller contact can remain.

This allows PublicnEUro to keep public metadata and identifiers available while matching file storage costs to the actual hosting or archival mode selected for each dataset.

Each service agreement has an end date. At the end of the agreement, the data controller and NRU can draw up a new agreement, leaving the dataset to hot storage or move it to archival storage, return the curated BIDS dataset to the institution, or remove the dataset files from the cloud.

When an agreement ends, the Data Processing Agreement requires personal data to be handed back or deleted at the instruction of the data controller. The agreement also requires termination assistance when requested. Succession arrangements are therefore handled primarily at dataset level. 

## Metadata and identifiers

PublicnEUro maintains dataset metadata and DOI landing pages independently of whether files are immediately available. If files are archived, retired, withdrawn or superseded, the public dataset record can be updated to show the appropriate lifecycle status and access condition.

This separation supports continuity even when file hosting changes. Users can still discover the dataset, cite the DOI, understand the lifecycle state, and see whether files are available from PublicnEUro, delayed in cold storage, available from the data controller, withdrawn, or superseded by another version.

The detailed lifecycle states, retrieval modes and public-record expectations are described in the [Preservation and dataset lifecycle policy](preservation-lifecycle.md).

## Service closure

Where service closure or non-renewal affects a dataset, PublicnEUro will update the dataset metadata and access condition so users can distinguish between datasets that are active, archived, retired, withdrawn or superseded. The goal is to avoid broken expectations: file access may end, move or be delayed, but the public record remains clear and traceable wherever legally possible.

For full repository closure, PublicnEUro will, where legally and practically possible, notify affected data controllers, stop accepting new deposits, complete pending access and agreement records, export or return hosted data according to controller instructions, preserve public metadata and DOI landing pages, and document the final retrieval route or closure status for each dataset.
